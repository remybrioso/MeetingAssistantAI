# Meeting Assistant AI v0.9.0-alpha.3

Status: Internal prerelease / private repository.

## 1. Purpose

Esta prerelease cierra el hardening derivado de Corporate Acceptance sobre `v0.9.0-alpha.2`. Su objetivo es entregar a los testers internos de TSS una build con mayor integridad temporal y semántica, almacenamiento correcto de reuniones importadas y una experiencia controlada cuando el contenido no aporta evidencia suficiente para producir una minuta.

## 2. Changes since alpha.2

- Compatibilidad reforzada con los contratos de salida estructurada de la versión local de Ollama utilizada por MAI.
- Normalización de discontinuidades temporales de Faster-Whisper mayores de 10 segundos antes del chunking.
- Reconciliación determinista de cobertura fuente en la consolidación semántica global.
- Fallback explícito a consolidación de identidad cuando una referencia fuente queda reutilizada ambiguamente entre varios elementos.
- Procedencia narrativa limitada a los elementos semánticos que realmente fundamentan cada texto.
- Reuniones importadas almacenadas bajo la misma ruta canónica de Meetings utilizada por las reuniones normales.
- Resultado de evidencia insuficiente tratado mediante excepciones de dominio y un aviso comprensible, sin falso éxito ni exportación.
- Corrección de la colisión de nombres que impedía la colección global predeterminada de pytest.

## 4. What testers should validate

- Inicio de MAI y evaluación correcta de capacidades en el Setup Wizard.
- Captura de una reunión normal y creación de su sesión bajo la ruta canónica de Meetings.
- Importación de un WAV y creación de la sesión bajo esa misma raíz canónica.
- Generación completa de `MeetingReport` y de los artefactos JSON, Markdown, DOCX y PDF para una reunión con evidencia suficiente.
- Conservación de audio, transcripción y métricas, sin habilitar Exportar, cuando la evidencia sea insuficiente.
- Disponibilidad de audio de micrófono y, cuando el equipo lo soporte, captura loopback de audio del sistema.

## 5. Installation / upgrade

El instalador de alpha.3 está diseñado para una instalación por usuario. Para una actualización normal desde alpha.2, ejecuta el nuevo instalador sobre la instalación existente; no es necesario desinstalar alpha.2.

Las reuniones normales e importadas nuevas se almacenan bajo la ruta canónica de Meetings dentro de Documents, incluida la redirección de Documents a OneDrive configurada por Windows.

Consulta `develop/docs/INSTALLATION.md` antes de realizar una desinstalación o una validación clean-install.

## 6. Known limitations

- Windows x64.
- El instalador no está firmado digitalmente; SmartScreen puede mostrar una advertencia.
- No existe un actualizador automático.
- Ollama permanece como dependencia externa.
- La captura de audio del sistema depende del soporte de loopback.
- Las primeras descargas de modelos requieren Internet.
- Las sesiones importadas legacy bajo `{app}\output` no se migran automáticamente.

## 7. Legacy imported-session warning

Versiones anteriores a CAT-002 pueden haber creado sesiones importadas bajo:

```text
%LOCALAPPDATA%\Programs\Meeting Assistant AI\output
```

Alpha.3 no migra esas sesiones automáticamente. Antes de desinstalar alpha.2 o realizar una validación clean-install en un perfil afectado, crea una copia de seguridad del directorio `output` COMPLETO.

## 8. Artifact contract

Artefactos del proceso de release:

```text
MeetingAssistantAI.exe
MeetingAssistantAI-Setup-v0.9.0-alpha.3.exe
MeetingAssistantAI-Setup-v0.9.0-alpha.3.exe.sha256
```

El bundle one-folder que contiene `MeetingAssistantAI.exe` es un artefacto intermedio de packaging que debe validarse antes de construir el instalador. La GitHub Release publica el instalador y su checksum.

Estos artefactos todavía no se consideran construidos ni validados para alpha.3. Deben generarse únicamente después de congelar `RELEASE_SHA`.
